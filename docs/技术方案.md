# 技术方案：个人 Agent Harness（状态 + 交接 + 薄路由层）

> 定稿决策：D1 个人（gitignore）· D2 增加 CLAUDE.md 入口 · D3 ai-memory 后续加（先手搓 + 附试装清单）。
> 分发形态：做成可复用母版仓库 `lucky-Luor/agent-harness`，任意项目 `install.sh` 装入。

## 1. 背景与目标

### 1.1 要解决的真问题
核心诊断——当前瓶颈不是系统 bug、不是空转，而是**上下文过重**，有 30–40% 优化空间。典型表现：

| 症状 | 现状 |
|---|---|
| 规范文档越堆越大，每个任务全量读 | 如 homad `AGENTS.md` 已 19KB + `docs/` 十几个子目录 |
| 跨会话 / 跨 Agent 无交接 | 从 Codex 切 Claude 要重讲一遍 |
| "任务干到哪了"散落 | 混在 plans 里，没有活动任务一览 |
| 重复踩坑 | 没地方记"哪些方案已试过且失败" |

### 1.2 目标（可验收）
1. 新会话/新 Agent 在第一个 prompt 前能定位"上次干到哪、下一步从哪接、哪些坑别再踩"。
2. 单任务启动只读必要信息，不再全量 load `AGENTS.md` + 全套 docs。
3. 人写规范（`AGENTS.md`）与 Agent 临时笔记物理隔离，后者不获得规范权威。
4. 零新增依赖即可跑；可选叠加 `ai-memory` 做自动化交接。

### 1.3 非目标
- 不重造 `AGENTS.md`（它是 constitution/standards 层，已做对）。
- 不引入 BMAD 这类重角色扮演框架（~31k token/次，对日常 bugfix 是杀鸡用牛刀）。
- 不叠第二套记忆检索层（beatrice_memory 已够且更结构化）。

## 2. 设计原则（对应已验证来源）
| 原则 | 来源 | 落地 |
|---|---|---|
| 薄路由 + 渐进式披露 | 视频 / Cline Memory Bank 被批"开头读全部不 scale" | `GUIDE.md` 只给指针不给内容 |
| 人写规范 vs Agent 笔记物理隔离 | Agent OS 分层 | `.agent-hub/` 与 `AGENTS.md`/`docs/` 分开 |
| delta 而非全量重述 | OpenSpec | `status.md` 只记本次增/改/删 |
| 交接含"失败方案"栏 | ai-memory（Cline 版缺此栏） | `handoff.md` 三段：停在哪/失败方案/待解 |
| 自称完成不算数 | 视频教训 | `status.md` 强制"验证证据"栏 |

## 3. 目标架构

### 3.1 母版仓库（可复用、项目无关）
```
agent-harness/
├── install.sh                 # 一键装进目标项目
├── templates/
│   ├── .agent-hub/            # 拷进目标项目的个人工作区(占位符)
│   │   ├── GUIDE.md
│   │   ├── tasks/_index.md
│   │   └── templates/{status,handoff}.md
│   └── CLAUDE.md              # 目标项目根的 Claude 入口
├── examples/homad-GUIDE.md    # 填好的真实样例
└── docs/技术方案.md            # 本文件
```

### 3.2 装入目标项目后的运行态
```
<项目>/
├── AGENTS.md                  # 团队规范(原有, 不动, 提交)
├── CLAUDE.md                  # Claude 入口(个人, gitignore)
└── .agent-hub/                # 个人任务状态 + 交接(gitignore)
    ├── GUIDE.md
    ├── tasks/_index.md
    ├── tasks/<任务id>/{status,handoff}.md
    ├── archive/
    └── templates/
```

### 3.3 各层职责与边界（谁负责什么，不重叠）
| 层 | 存什么 | 生命周期 |
|---|---|---|
| `AGENTS.md` / `docs/` | 人写规范、领域知识、正式方案 | 长期、提交 |
| `docs/plans/` | 正式方案与里程碑（团队可见） | 提交 |
| `.agent-hub/` | 会话级临时状态、交接、私人薄路由 | 随时可删、gitignore |
| beatrice_memory | 跨会话偏好/决策/约束 | 持久、结构化 |

> `docs/plans/` 放"决定做什么、为什么"；`.agent-hub/tasks/` 放"现在干到哪、下个会话怎么接"。
> `status.md` 用一行链接指向对应 `docs/plans/xxx.md`，不抄内容。

## 4. 关键文件规格
- `GUIDE.md`（薄路由，目标 < 60 行）：开工 30 秒流程 + 任务类型映射表 + 验证钩子 + 持久层分工 + ai-memory 三步试装清单。
- `tasks/_index.md`：活动任务一览（id·标题·状态·关联方案·更新）。
- `status.md`：本次改动（delta 增/改/删）+ 进度 + 阻塞 + **验证证据（命令+结果）**。
- `handoff.md`：停在哪 / 已试过且失败的方案 / 待解问题。
- `CLAUDE.md`：Claude Code 根入口，导流到 `GUIDE.md` + `AGENTS.md`，含 Claude/Codex 双入口说明。

## 5. 分发与安装
```bash
git clone https://github.com/lucky-Luor/agent-harness.git
cd agent-harness && ./install.sh /path/to/项目
```
`install.sh`：拷 `.agent-hub/`（-n 不覆盖）+ `CLAUDE.md`（已存在则跳过），并把这两项追加进目标 `.gitignore`（幂等去重，保持个人、不污染团队仓库）。

## 6. 验收标准
- 新开会话只读 `CLAUDE.md → GUIDE.md → 目标任务 handoff.md`（合计 < 5KB）即可接手，不需全量读 `AGENTS.md`。
- `status.md` 验证证据栏是真实命令+结果，而非"已测试完成"。
- 母版仓库 `clone` 后 `install.sh <项目>` 可在新项目复用。

## 7. 后续升级路径（D3）
手搓版跑顺后试装 [ai-memory](https://github.com/akitaonrails/ai-memory)：git 版本化 markdown wiki + SQLite 全文索引，Claude Code / Codex 皆一等公民，支持零 LLM 模式（不烧 token），交接是 typed/owned/claimed-once 协议。顺手则状态交接交给它自动跑，`.agent-hub/` 只留薄路由 + 模板。
